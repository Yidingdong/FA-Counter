OPEN ABOUT THE PROCESS

From voice to number.

This is an automated estimate reviewed by the operator. The public website displays a result; it does not listen to visitors or run speech recognition in their browsers.

  1. 01

    Capture on a laptop

    The operator’s microphone records audio. Live mode defaults to 4-second windows, with a short overlap to give words near a cut more context.

  2. 02

    Transcribe with Whisper

    Audio windows are sent to OpenAI’s whisper-1 transcription API using the operator’s key. The result includes text and word timestamps.

  3. 03

    Count locally

    The laptop finds whole-word matches. Timestamps assign overlapping audio to one window to reduce duplicate counting.

  4. 04

    Publish a small snapshot

    An authenticated laptop request sends the count, lecture date, and live flag to a hosted relay. The relay adds an update time and stores the latest snapshot.

  5. 05

    Display publicly

    This GitHub Pages site reads the relay about once per second. The statistics above are calculated from the count changes this browser receives.

What counts as “ja”?

The default counts the complete word “ja”, ignoring case and surrounding punctuation. “Java” does not count. The operator can also enable “yeah”/“ya”, estimate sentence-ending uses, exclude detections, or adjust the total manually. The current public feed does not report which options are selected.

Why isn’t it instant?

Audio must first fill a window, then be uploaded and processed. Up to two transcription windows can be in flight, but results are applied in recording order. Publishing and the website’s next check add more delay. The operator can choose 4-, 8-, or 12-second live windows.

What is shared?

Audio is sent to OpenAI for transcription. Recordings, transcripts, detailed word frequencies, API keys, and the publishing credential are not delivered to public visitors. The relay is a Cloudflare Worker hosted through Sites. Its R2 storage holds the latest JSON count snapshot, not an audio recording. Visit statistics stay in this tab’s memory and restart when it is reloaded.

What can be wrong?

Noise, other speakers, short interjections, and switching between English and German can cause missed or incorrect words. The microphone does not identify the professor. Updates may arrive in batches, and manual corrections can lower the count. These visit statistics are not full-lecture averages or a measure of recognition accuracy.

Total spoken words, word frequencies, and full-lecture duration are not currently shared by the running counter. Those statistics can be connected later without guessing values here.
